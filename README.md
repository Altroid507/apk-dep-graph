работ по дисциплине «Конфигурационное управление».

## Общее описание

`apk-dep-graph` — консольная утилита, которая:

1. Читает параметры запуска из CSV-файла конфигурации.
2. Извлекает информацию о прямых зависимостях заданного пакета
   из `APKINDEX.tar.gz` репозитория Alpine Linux
   **без использования `apk` и сторонних библиотек** для получения
   зависимостей.
3. Строит транзитивный граф зависимостей с учётом максимальной
   глубины анализа и корректно обрабатывает циклические зависимости.
4. Поддерживает вывод обратных зависимостей (пакетов, которые
   зависят от заданного).
5. Формирует текстовое представление графа на языке диаграмм
   **PlantUML** и сохраняет изображение графа в файл формата **SVG**.
6. По запросу выводит граф зависимостей в виде **ASCII-дерева**.

Утилита написана на Python 3.11+ и использует только стандартную
библиотеку.

## Функции и настройки

Все параметры, настраиваемые пользователем, задаются в
CSV-файле конфигурации. Формат файла — по одной паре
`ключ,значение` на строку. Строки, начинающиеся с `#`,
игнорируются.

| Ключ              | Тип     | Описание                                                    |
|-------------------|---------|-------------------------------------------------------------|
| `package`         | строка  | Имя анализируемого пакета. Обязательный.                    |
| `repository`      | строка  | URL apk-репозитория или путь к файлу тестового графа.       |
| `test_mode`       | bool    | `true` — использовать локальный файл описания графа.        |
| `package_version` | строка  | Версия пакета. Обязательный.                                |
| `output_image`    | строка  | Путь к SVG-файлу с изображением графа. По умолчанию `graph.svg`. |
| `ascii_tree`      | bool    | Выводить ли зависимости в виде ASCII-дерева.                |
| `max_depth`       | int     | Максимальная глубина анализа зависимостей (1..64).          |

Булевы значения принимаются в виде `true/false`, `1/0`, `yes/no`
(регистр не важен).

Дополнительные опции командной строки:

| Опция               | Описание                                                |
|---------------------|---------------------------------------------------------|
| `--config PATH`     | Путь к CSV-файлу конфигурации (обязательный).           |
| `--reverse PACKAGE` | Вывести обратные зависимости для указанного пакета.     |

### Режимы работы

**Реальный режим** (`test_mode = false`):

- Из указанного URL скачивается `APKINDEX.tar.gz` и распаковывается
  в память.
- В индексе ищется запись, соответствующая паре
  `package` + `package_version`.
- Из поля `D` извлекаются имена прямых зависимостей; версионные
  ограничения (`=`, `>`, `<`, `~`) отбрасываются.

**Тестовый режим** (`test_mode = true`):

- Вместо URL используется путь к локальному файлу описания графа.
- Каждая строка файла — одно ребро `A B`, где `A` и `B` — имена
  пакетов большими латинскими буквами.
- Пустые строки и строки, начинающиеся с `#`, игнорируются.
- Пример файла:

  ```
  A B
  A C
  B D
  C D
  D E
  ```

### Обработка ошибок

При некорректных значениях параметров утилита завершается с
сообщением об ошибке в `stderr` и ненулевым кодом возврата:

- `ConfigError` — ошибки конфигурационного файла (неизвестный ключ,
  некорректный тип, отсутствующий обязательный параметр, глубина
  вне допустимого диапазона).
- `GraphFileError` — ошибки локального файла тестового графа.
- `RepositoryError` — ошибки доступа к репозиторию (сеть, отсутствие
  файла `APKINDEX.tar.gz`).
- `PackageNotFoundError` — запрошенный пакет не найден в индексе.

## Сборка и запуск

### Требования

- Python 3.11 или новее.
- Для разработки: `pytest`, `ruff`.
- Для визуализации в SVG — доступ к `https://www.plantuml.com`
  (или локальный PlantUML-сервер).

### Установка

```bash
# Клонирование
git clone <URL-репозитория> apk-dep-graph
cd apk-dep-graph

# Создание виртуального окружения (по желанию)
python3 -m venv .venv
source .venv/bin/activate

# Зависимости для разработки
pip install pytest ruff
```

### Запуск

```bash
# Через run.sh
./run.sh --config config.example.csv

# Или через make
make run

# Или напрямую модулем
PYTHONPATH=src python3 -m src --config config.example.csv
```

### Тесты

```bash
make test
# или
PYTHONPATH=src python3 -m pytest -q
```

### Линтер

```bash
make lint
# или
ruff check src tests
```

## Примеры использования

### Пример 1. Реальный репозиторий Alpine

Файл `musl.csv`:

```csv
package,musl
repository,https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64
test_mode,false
package_version,1.2.5-r0
output_image,musl.svg
ascii_tree,true
max_depth,3
```

Запуск:

```bash
./run.sh --config musl.csv
```

Ожидаемый результат:

- Вывод всех параметров конфигурации в формате `ключ=значение`.
- Список прямых и транзитивных зависимостей пакета `musl` до
  глубины 3.
- Файл `musl.svg` с изображением графа (PlantUML).
- ASCII-дерево зависимостей в консоли.

### Пример 2. Обратные зависимости

```bash
./run.sh --config musl.csv --reverse musl
```

Дополнительно к предыдущему выводу будет напечатан список
пакетов, которые (транзитивно) зависят от `musl`.

### Пример 3. Тестовый режим на простом графе

Файл `test_simple.csv`:

```csv
package,A
repository,tests/fixtures/simple_graph.txt
test_mode,true
package_version,1.0
output_image,test.svg
ascii_tree,true
max_depth,5
```

Граф `tests/fixtures/simple_graph.txt`:

```
A B
A C
B D
C D
D E
```

Запуск:

```bash
./run.sh --config test_simple.csv
```

### Пример 4. Тестовый режим на графе с циклом

Файл `tests/fixtures/cycle_graph.txt`:

```
A B
B C
C A
C D
```

Файл `test_cycle.csv`:

```csv
package,A
repository,tests/fixtures/cycle_graph.txt
test_mode,true
package_version,1.0
output_image,cycle.svg
ascii_tree,true
max_depth,10
```

Запуск:

```bash
./run.sh --config test_cycle.csv
```

Утилита корректно завершит обход, несмотря на цикл `A → B → C → A`.

## Ограничения и сравнение со штатными средствами

Штатные средства Alpine предоставляют:

- `apk info -R <pkg>` — список прямых зависимостей пакета;
- `apk dot <pkg>` — граф зависимостей в формате Graphviz.

Возможные расхождения с результатами `apk-dep-graph`:

1. **Виртуальные пакеты.** `apk` учитывает виртуальные зависимости
   вида `so:libc.musl-x86_64.so.1`, `cmd:sh`, `pc:zlib`. Парсер
   `apk-dep-graph` извлекает только «текстовые» имена зависимостей
   из поля `D` записи APKINDEX.
2. **Приоритеты и конфигурация.** `apk dot` использует текущую
   конфигурацию репозиториев (`/etc/apk/repositories`) и приоритеты
   пакетов, тогда как `apk-dep-graph` работает с одним конкретным
   APKINDEX по указанному URL.
3. **Разрешение версий.** `apk info` показывает зависимости уже
   установленного пакета (с учётом выбранных версий), а
   `apk-dep-graph` ищет ровно ту версию, которая указана в
   `package_version`.
4. **Раскрытие виртуальных пакетов.** `apk` может раскрывать
   виртуальные пакеты в конкретные реализации, а `apk-dep-graph`
   этого не делает.

Перечисленные расхождения объясняются тем, что `apk-dep-graph`
сознательно реализует минимальный парсер APKINDEX без обращения
к `apk` (как и требуется условием практической работы).

## Тестирование

Тесты покрывают:

- **`test_config.py`** — загрузка CSV-конфигурации, обработка
  неизвестных ключей, некорректных булевых значений и глубины.
- **`test_apk_parser.py`** — разбиение и разбор записей APKINDEX,
  отбрасывание версионных ограничений.
- **`test_graph.py`** — дедупликация рёбер и обратный граф.
- **`test_traversal.py`** — рекурсивный BFS с ограничением
  глубины, устойчивость к циклам, поиск обратных зависимостей.
- **`test_ascii_tree.py`** — ASCII-дерево с защитой от циклов.

Запуск тестов:

```bash
make test
```

Ожидаемый результат: все тесты проходят.
